# study/ の作業ルール

## 並べ方

- 上から順に読めるように並べる。前の節やノートで説明していない言葉は使わない。
- 各ノートの先頭に「前提」の表を置く。前のノートのどの言葉を使うかを書く。
- 各ノートの最後に「このリポジトリでの使われ方」の表を置く。README の節と notes/ の節を挙げる。そのあとに「Lean での対応」の表（概念、Lean の名前、ファイル）を置く。

## 中身

- 定義を先に書き、そのあとに小さい例を書く。
- 定理には証明か、証明の概略を付ける。ここで証明しないことは、そう書く。
- 例の値を計算したときは、計算の方法（手計算か計算機か）を書く。
- 本文では形式化（証明支援系）について書かない。形式化での名前、ファイル、コードは、最後の「Lean での対応」の表にだけ書く。定理や対象には、数学の名前か番号（「性質 2」「§8 の補題 1」など）を付ける。
- 1-Y 版（[koteitan/1y-wo-por](https://github.com/koteitan/1y-wo-por) の study/）と同じ数学は、1-Y 版と同じ文と式で書く。変えるのは、数学が違うところだけである。

## 文

- 短い文で書く。1 つの文に 1 つのことを書く。
- 比喩を使わない。文字どおりの言葉で書く。
- 数式で書けることは数式で書く。

## 数式（GitHub で表示するため）

- 文中の数式は `` $`...`$ `` の形で書く。
- 別行の数式は ```` ```math ```` の囲みで書く。
- 文中の数式では、不等号を `\lt`、`\gt` と書く。
- 行の区切りは `\cr` を使う。バックスラッシュを 2 つ並べる書き方は使わない。
- 箇条書きの中では、囲みの数式を使わない。文中の数式だけを使う。
- 表のセルの中の数式に `|` を書かない。`\mid` を使う。

## ほかのプロジェクトの参照

- ほかのプロジェクトは、公開されている GitHub の URL で参照する。ローカルのパスは書かない。
